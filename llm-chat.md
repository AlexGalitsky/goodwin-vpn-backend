## 1. Архитектура и Масштабирование (Multi-node)
У тебя уже есть plane и agent, что ставит проект на уровень Marzban. Чтобы развить это, зрелые панели используют: [1, 4] 

* Балансировка нагрузки (Load Balancing): Возможность привязать пользователя не к одной группе/ноде, а к пулу нод. Панель или сам клиент (через Subscription) балансирует трафик между ними.
* Fallback-ноды (Отказоустойчивость): Если agent на ноде умирает (или забанен IP), панель автоматически переключает пользователей на резервный сервер без изменения Subscription URL. [2] 
* Поддержка СУБД: Переход с дефолтного SQLite на PostgreSQL/MySQL для распределенной работы панели. [1, 3] 

## 2. Управление Лимитами и Квотами (Расширенный P7)
У тебя заложен отличный фундамент, но у конкурентов эта логика проработана глубже:

* Периодические лимиты (Resetting Quotas): Сброс квот каждый день / неделю / месяц (например, «5 ГБ в день», а не просто «100 ГБ на месяц»). [1, 4] 
* Динамическое ограничение скорости (Throttling): Вместо полной блокировки (Disable) при исчерпании лимита, скорость пользователя режется до условных 256 кбит/с.
* Лимит по IP (Concurrent Connections): Ограничение количества устройств, одновременно сидящих под одним токеном (например, максимум 2 разных IP за последние 15 минут). Защищает от «шеринга» одной подписки со всем интернетом. [3] 

## 3. Продвинутый Subscription Engine
Subscription URL — это сердце системы. В современных панелях он умеет:

* Мульти-форматность: Отдача конфигов не только под свой Flutter-клиент, а генерация универсальных форматов (Base64, Clash, Sing-box, Shadowrocket, V2ray). Это привлекает пользователей, которые любят свои кастомные приложения. [1, 4] 
* User JSON / Спецификация: Отдача клиенту информации о его профиле. Продвинутые клиенты читают HTTP-заголовки ответа (Profile-Update-Interval, Profile-Title) или JSON, чтобы прямо в приложении рисовать красивый прогресс-бар: "Осталось 12 ГБ из 50, продлить до 2027 года".

## 4. Протоколы и Обход Блокировок (Продвинутый транспорт)
Hysteria2 и REALITY — это база. Но для «непробиваемости» добавляют: [2, 3, 5] 

* WARP/IP-Residential Routing: На самой ноде настраивается роутинг (через Xray/Sing-box), чтобы трафик на Netflix/ChatGPT шел через Cloudflare WARP или локальный прокси, предотвращая капчи и блокировки по геопозиции. [6] 
* Фейковые сайты (Camouflage): Для REALITY/Hysteria веб-сервер на ноде на порту 443 при обычном HTTP/HTTPS запросе должен отдавать реальный работающий сайт (какой-нибудь зарубежный книжный магазин), маскируя прокси под обычный веб-трафик.

## 5. Интеграции, Уведомления и Мониторинг (P8+)

* Telegram-бот для пользователей: Полноценный self-service. Пользователь в чате с ботом нажимает кнопки: «Мой статус», «Скачать конфиг», «Купить/Продлить». Бот сам стучится в API панели.
* Система уведомлений (Webhooks): Отправка алертов в Telegram/Discord админу: "Нода Германия-1 упала", "Память на ноде >90%", "У пользователя user_1 заканчивается трафик".
* Мульти-админы и RBAC: Разделение прав. Главный админ (Owner) и субадмины (Реселлеры), которые могут создавать пользователей только в рамках выделенной им общей квоты трафика. [4, 7, 8, 9] 

## 6. Бизнес-фичи (Биллинг)
Если проект планирует монетизироваться, в панель встраивают:

* Интеграцию платежных шлюзов (ЮKassa, Stripe, CryptoMus, Telegram Stars) для автоматического продления.
* Генератор промокодов и реферальную систему.

Когда проект перерастает рамки одной ноды, управление «зоопарком» протоколов и конфигураций становится главной головной болью. Панели вроде 3X-UI, Marzban и Hiddify решают эту задачу через глубокую абстракцию и автоматизацию на стороне агента.
Вот полный список фич, которые необходимы для профессионального конфигурирования нод и управления протоколами:
------------------------------
## 1. Архитектура управления агентами (Node & Agent Management)

* Централизованный Upstream обновлений: Автоматическое обновление бинарников ядра (Xray, Sing-box, Hysteria) на нодах через plane. Панель сама пушит новую версию на agent, либо агент сверяет версии при запуске.
* Кастомное ядро (Custom Core Selection): Возможность выбора форка ядра прямо из админки для конкретной ноды (например, переключение ноды с официального Xray-core на XTLS/Xray-core с поддержкой специфических патчей).
* Health Check & Auto-Restart: Агент не просто «исчезает» при смерти, а собирает логи ошибок ядра (например, порт занят, сертификат просрочен) и шлет их в панель. При падении процесса ядра агент пытается перезапустить его локально (Watchdog).

## 2. Управление транспортом и обходом блокировок (Advanced Transport)

* Динамическое маскирование (Camouflage Fallbacks): Конфигурирование полноценного веб-сервера (Nginx/Caddy или встроенного в ядро) на порту 443. Если на ноду стучится цензор (простой GET-запрос), нода показывает ему реальный чужой сайт (например, зеркало блога или интернет-магазина).
* Автоматический подбор SNI (Dest-scanning): Встроенный в панель сканер, который помогает админу находить «чистые» домены для REALITY (Destination IP/SNI), которые не заблокированы в целевой стране (например, для Ирана или Китая нужен свой набор SNI, для РФ — другой).
* Мульти-сертификация: Автоматическая генерация и ротация не только Let's Encrypt (HTTP-01), но и поддержка DNS-01 челенджей (через Cloudflare/Cloudns API), чтобы получать SSL-сертификаты на ноды без открытия 80-го порта.

## 3. Маршрутизация на ноде (On-Node Routing / Outbounds)
Самая мощная фича зрелых панелей — управление тем, куда нода отправляет трафик дальше:

* WARP-роутинг (Cloudflare Integration): Конфигурирование ноды так, чтобы трафик на заблокированные в РФ сайты (Instagram, LinkedIn) или сервисы с защитой от хостинг-провайдеров (ChatGPT, Netflix) автоматически заворачивался внутри ноды в бесплатный туннель Cloudflare WARP. Пользователь этого не видит, для него «просто всё работает».
* Блокировка по GeoIP / Torrent / Рекламе: Прямо из панели на ноду пушатся правила: блокировать BitTorrent-трафик (чтобы хостинг не прислал DMCA-абузу), блокировать порты 25/465 (защита от спам-рассылок), или вырезать рекламу на уровне DNS ноды.
* IP-Residential / Чейнинг (Proxy Chaining): Возможность пустить трафик с твоей быстрой ноды (например, в Амстердаме) дальше через дешевый резидентский прокси-ноду (в конкретном домашнем провайдере), чтобы обойти строгие анти-фрод системы банков.

## 4. Оркестрация портов и мульти-протокольность (Port Management)

* Port Sharing (Мультиплексирование): Запуск VLESS-REALITY, Shadowsocks и Trojan на одном и том же 443 порту (TCP) с помощью разделения трафика на основе TLS ALPN (протокол под капотом понимает, кто стучится, и перенаправляет на нужный внутренний порт).
* Динамические порты (Port Hopping): Полезно для Hysteria2/TUIC (UDP). Чтобы провайдер не заблокировал UDP-порт за высокую скорость, панель настраивает на ноде пул портов (например, UDP 20000-30000), а клиент постоянно меняет порты при подключении (Port Hopping), обходя глушилки.
* Автоматическое управление брандмауэром (UFW/IPTables): Когда админ добавляет протокол или меняет порт в панели, agent сам прописывает нужные правила в iptables/nftables на ноде, закрывая все остальные неиспользуемые порты.

## 5. Мониторинг ресурсов нод (Node Telemetry)

* Real-time метрики: Агент собирает и передает в панель не только факт «жива/мертва», но и графики: CPU, RAM, Disk, Network I/O, а также PPS (Packets Per Second) — критически важный параметр, так как провайдеры часто блокируют ноды при аномальном всплеске PPS.
* Аудит соединений: Отображение активных сессий на конкретной ноде прямо сейчас (какие пользователи подключены, сколько их, из каких стран/IP, какие протоколы используют).

* Аудит соединений: Отображение активных сессий на конкретной ноде прямо сейчас (какие пользователи подключены, сколько их, из каких стран/IP, какие протоколы используют).
